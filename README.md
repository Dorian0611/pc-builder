# PC Builder (Hungarian)

A free, serverless PC part picker for the Hungarian market: pick components, get a
compatibility check, an estimated price in HUF and a power estimate. Builds can be shared
as links (`#b=…`, part ids packed into the URL – no server) and saved by name in the browser.
An upgrade advisor suggests what to replace in an existing build, based on our own rough
performance scores (`scripts/perf.mjs`: CPU from architecture, clock, cores and cache; GPU from
a per-chip table). The FPS estimate covers Steam's most played games, refreshed twice a month
from their store requirements (`scripts/games/`), plus hand-kept entries such as GTA VI
(`data/games-manual.json`, marked as estimates).
The user interface is in Hungarian.

Live site: https://dorian0611.github.io/pc-builder/

```
npm install
npm run dev     # dev server: http://localhost:5173
npm test        # compatibility rule tests
npm run build   # static build into dist/
```

## Layout

- `public/data/*.json` – part data (BuildCores OpenDB, CC BY-NC-SA 4.0), generated by
  `node scripts/import-opendb.mjs vendor/opendb`
- `src/lib/compat.ts` – compatibility rules and power estimate
- `src/lib/catalog.ts` – data loading, categories
- `src/lib/share.ts` – build links and builds saved in the browser
- `src/lib/upgrade.ts` – upgrade advisor (bottleneck, swaps with the best gain per budget)
- `src/components/` – UI
- `src/test/fixtures/` – small hand-written part list for tests
- `.github/workflows/deploy.yml` – test, build and deploy to GitHub Pages on every push to `main`

## Prices

Prices are collected twice a month (1st and 15th, `.github/workflows/update-prices.yml`): one job per
shop runs `scripts/prices/collect.mjs` in parallel, then `scripts/prices/update-prices.mjs --offers-dir`
merges them:

1. each source in `scripts/prices/sources/index.mjs` returns shop offers:
   - `manual` – `data/offers/manual.csv`;
   - `pcx` – walks the ~130-page component listing; part number from the product name or URL;
   - `arukereso` – Árukereső / Árgép product pages listed in `data/arukereso-urls.csv`
     (`partId,url,note`), scraped by the Apify actor `zinc_grill/arukereso-argep-scraper`
     (needs the `APIFY_TOKEN` secret, ~$1 per 1,000 pages, cap `ARUKERESO_MAX_URLS`, default 500).
     Every shop offer on the page counts. This actor gets past the sites' bot protection itself;
     it is an explicit exception to the rule below, chosen by the project owner;
   - `sources/sitemap-shop.mjs` – generic sitemap → product page → schema.org JSON-LD source for
     further shops: only pages whose URL contains a known part number are fetched, and an offer
     counts only if the page's own MPN/EAN belongs to that part.

   Rule: a shop is collected only if robots.txt allows it and it serves the identified bot
   (`pc-builder-price-bot`) from GitHub Actions without a CAPTCHA, bot check or block; such checks
   stop the source (`http.mjs`) and are never worked around. Checked and not included: iPon
   (CAPTCHA), eMAG (HTTP 511), Aqua and Alza (403), MediaMarkt (prices only via JavaScript),
   Euronics (empty sitemap). One request at a time with a 3 s pause. Off switch: repository
   variable `PCX_DISABLED` = `1`;
2. offers are matched to parts by EAN or manufacturer part number (`data/part-identifiers.json`,
   written by the OpenDB importer); identifiers shared by several parts are ignored;
3. per part: median price, lowest price, number of distinct shops → `public/data/prices.json`;
4. a part without fresh offers keeps its last price for up to 35 days; a median change over 40% is flagged;
5. changed prices are appended to `data/price-history/YYYY-MM.csv`.

**Foreign shops** (`megekko` NL, `overclockers` UK; sources with `foreign: {country, currency}`) never
become real prices. Their offers are converted with the ECB daily rates to a Hungarian gross price
(`fx.mjs`: net of the shop country's VAT, plus 27%) and written to `public/data/foreign-prices.json`
with per-category calibration factors (median Hungarian/foreign ratio over parts that have both,
`foreign.mjs`). Shops were chosen with `scripts/prices/probe-shops.mjs` run from GitHub Actions
(`.github/workflows/probe-shops.yml`).

Parts without a shop price get an **estimate** in the browser (`src/lib/estimates.ts`): first their
own foreign median × the category factor, else the median
of comparable priced parts (same GPU chip + VRAM, same CPU, same SSD size/interface, …), shown
with its 25–75% range and always labelled as an estimate.

A failing source doesn't stop the others, but the workflow fails so GitHub sends an e-mail.
To add a source, create `scripts/prices/sources/<name>.mjs` exporting `name` and
`fetchOffers()` (see `manual.mjs`), then add it to `SOURCES`.

```
node scripts/prices/update-prices.mjs   # run locally
```
